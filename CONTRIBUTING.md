# Contributing to Anu

Thanks for your interest! Anu is a pure-Swift, on-device agentic AI app for
iOS 17+. This guide covers the non-obvious bits of the build so you can get to
a green build and test run quickly.

## Prerequisites

- **Xcode 26.5+** (iOS 26.5 SDK) on Apple Silicon.
- **CocoaPods** (`gem install cocoapods`) — used for the MediaPipe / LiteRT SDK.
- **Python 3** — the Xcode project is generated by a script.
- **SwiftLint** (`brew install swiftlint`) — run before pushing.

## The generated Xcode project (important)

`Anu.xcodeproj` is **generated** by [`generate_xcodeproj.py`](generate_xcodeproj.py).
Do not hand-edit `project.pbxproj`. When you add or remove a Swift file:

1. Add/remove it in the `SWIFT_FILES` (or `TEST_FILES`) list in the script.
2. Regenerate, then reinstall pods:

   ```sh
   python3 generate_xcodeproj.py
   LANG=en_US.UTF-8 pod install
   ```

The script uses deterministic UIDs and is safe to re-run.

### Models are not in the repo

The on-device model files (`*.litertlm`, `*.mlpackage`, `tokenizer.json`) are
large and **gitignored**. The generator includes them as bundle resources
**only when present on disk**, so a fresh checkout regenerates a *model-free*
app that still builds and runs the full test suite (tests use the in-repo
`ScriptedModel`). To run the real on-device model, place the model files under
`Anu/` and regenerate. See the [README](README.md) for model conversion.

## Build & test

Always use the **workspace** (CocoaPods), not the bare project:

```sh
# Build everything (app + Widget + Share extensions + test bundles)
xcodebuild build-for-testing \
  -workspace Anu.xcworkspace -scheme Anu \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -derivedDataPath build/DD -skipPackagePluginValidation

# Run the deterministic suite
xcodebuild test-without-building \
  -workspace Anu.xcworkspace -scheme Anu \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -derivedDataPath build/DD -skipPackagePluginValidation
```

The default test run is fully deterministic and green. Heavier tests are
**opt-in via environment variables** so CI stays fast and reliable:

| Env var | Enables |
| --- | --- |
| `REAL_MODEL_TEST=1` | Real on-device model smoke tests (needs model files) |
| `TEST_RUNNER_VERIFY_DRIVERS=1` | GUI verification drivers (screenshots) |
| `TEST_RUNNER_LIVE_CONNECTOR_TEST=1` | Live MCP catalog/registry network tests |
| `TEST_RUNNER_MCP_TEST_URL=<url>` | Live MCP round-trip against a real server |

## Linting

Run SwiftLint from the repo root before opening a PR:

```sh
swiftlint            # errors fail; long-line warnings are advisory
swiftlint --fix      # auto-correct what's safely correctable
```

Config lives in [`.swiftlint.yml`](.swiftlint.yml). Production code (`Sources`,
`AnuWidget`, `AnuShare`) is linted; tests are not.

## Pull requests

- Branch off `main`; keep PRs focused.
- CI must be green (lint + build + unit tests).
- If you added Swift files, confirm the project regenerates and pods install.
- Add tests for new behavior. UI changes should keep the deterministic UI
  tests green; add a driver if you add a surface.
- Follow the surrounding code's style and comment density.
