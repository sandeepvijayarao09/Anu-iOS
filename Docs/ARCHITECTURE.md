# Anu — Architecture & Documentation

> **Anu** is a voice-first, multimodal, **on-device agentic AI assistant for iOS**.
> Its brain is **Gemma 4 E4B** running entirely on the device via Google's
> LiteRT/MediaPipe engine. An on-device ML router decides, per message, what kind
> of task it is and which engine should answer. Private by default; the cloud is a
> sanitized, optional, user-gated fallback.

This document describes the *as-built* architecture: the layers, the data flow of a
single message, and the responsibilities of every subsystem. It complements the
[README](../README.md) (which covers setup) and
[PrivateComputeServer.md](PrivateComputeServer.md) (the optional private cloud backend).

---

## 1. The big picture

Anu is built around a single idea: **most requests should be answered on the device,
and the user should always be able to see exactly what (if anything) left it.**

Everything is coordinated by one `@MainActor` singleton, `AgentOrchestrator`, which is
the single source of truth for both the SwiftUI UI and the App Intents (Siri /
Shortcuts / Action Button / Widget). A user message flows through three decision
stages and then one of several execution modes:

```
                 ┌─ 🎤 voice (primary)  ─┐
   user input ───┼─ 🖼️  image            ─┼──► AgentOrchestrator.run()
                 └─ ⌨️  text             ─┘        (@MainActor singleton)
                                                        │
        ┌───────────────────────────────────────────────┴───────────────────────────┐
        │  ON-DEVICE DECISIONS  (no network, no model round-trip — milliseconds)       │
        │   1. TaskClassifier   NLEmbedding nearest-centroid →                          │
        │        casual · math · web · code · writing · QA                              │
        │   2. ModelClassifier  task + confidence + cloud-availability → a route        │
        │   +  MemoryStore      relevant saved notes injected as [M#] grounding         │
        │   +  PlanGate         is this *clearly* multi-step? (gates the planner)        │
        └───────────────────────────────────┬───────────────────────────────────────┘
                                             │
   ┌──────────────────┬──────────────────────┼───────────────────────┬──────────────────┐
   │ on-device CHAT   │ on-device AGENT       │ PLAN→EXECUTE→CRITIQUE  │ CLOUD (optional) │
   │ warm persona,    │ ReAct loop + tools    │ multi-step pipeline    │ Gemini / Private │
   │ fast, no tools   │ (≤6 iterations)       │ (planner + specialists │ Compute, PII-    │
   │                  │                       │  + synthesis + critic) │ scrubbed, gated  │
   └──────────────────┴──────────────────────┴───────────────────────┴──────────────────┘
                                             │
            Engine (swappable): LiteRT Gemma 4 E4B  ·  Core ML Gemma 3 4B  ·
            Apple Foundation Model  ·  Private Cloud   — streamed, cancellable
                                             │
                          PrivacyLedger logs every byte that leaves the device
```

### Design principles

| Principle | How it shows up in the code |
|---|---|
| **On-device first** | `ModelClassifier` keeps everything local unless a task clearly benefits from cloud *and* a key/endpoint is configured. |
| **Single source of truth** | `AgentOrchestrator.shared` is the only place conversation state lives; UI and Siri both drive it. |
| **Glass-box reasoning** | Every step is recorded as a `ReasoningStep` and rendered in `AgentTraceView`. |
| **Privacy is observable** | `PrivacyLedger` records every egress; a per-turn chip shows "everything on-device" or what left. |
| **No silent fakes in production** | A missing model becomes `UnavailableModel` (an explicit error); the `ScriptedModel` test double is `#if DEBUG` only. |
| **Swappable brain** | All engines conform to one `LocalLanguageModel` protocol; `ModelFactory` selects at launch. |
| **Bounded everything** | ReAct ≤ 6 iterations, planner ≤ 6 steps, one critic pass, one revision, tool timeouts (30 s). |

The app ships as **five Xcode targets**, all generated by code:

| Target | Type | Purpose |
|---|---|---|
| `Anu` | iOS app | The main assistant. |
| `AnuTests` | unit tests | ~51 test files (tool parsing, classifiers, tokenizer, PII, memory, orchestrator…). |
| `AnuUITests` | UI tests | Drive the real chat flow against the DEBUG `ScriptedModel`. |
| `AnuWidget` | Widget extension | Surfaces saved Workflows; runs them via `RunWorkflowIntent` (deliberately model-free). |
| `AnuShare` | Share extension | Accepts shared content and enqueues it for the app. |

Build tooling:

- **`generate_xcodeproj.py`** is the **source of truth** for the project (the
  project-as-code pattern, like XcodeGen/Tuist). The `.xcodeproj`/`.xcworkspace`
  are build artifacts. Re-run it after adding files or models; it bundles a present
  `.litertlm`/`.mlpackage` automatically and omits them when absent.
- **CocoaPods** provides MediaPipe (LiteRT runtime) — hence you open
  `Anu.xcworkspace`, not the `.xcodeproj`.
- **App Group** `group.com.anu.app` is shared by the app and its extensions for
  Workflows and the inbox queue.
- Swift 6 structured concurrency throughout: actor-isolated engines, a `@MainActor`
  orchestrator, `AsyncStream` generation wired to per-backend cancellation.

## 4. The Agent layer (the core)

This is what makes Anu *agentic* rather than a chat wrapper. It lives in
`Sources/Anu/Agent/`.

### 4.1 AgentOrchestrator — the hub

`AgentOrchestrator` ([AgentOrchestrator.swift](../Sources/Anu/Agent/AgentOrchestrator.swift))
is a `@MainActor final class` exposed as `.shared`. It owns the published UI state
(`messages`, `status`, `reasoningSteps`, `isThinking`, `pendingConfirmation`), the
swappable `model`, the `ToolRegistry`, the conversation history, and the multi-session
store. Its responsibilities are split across three files:

- **`AgentOrchestrator.swift`** — initialization, tool registration, the `run()` entry
  point, classification + routing, tool execution with a 30 s timeout, and the
  confirmation gate. The main message handler is `run(userMessage:imageData:)`
  ([AgentOrchestrator.swift:168](../Sources/Anu/Agent/AgentOrchestrator.swift):168).
- **`AgentOrchestrator+Modes.swift`** — the three generation modes: `chatTurn()`,
  `reactLoop()`, and `cloudTurn()`.
- **`AgentOrchestrator+Sessions.swift`** — privacy-sandbox lifecycle (create / switch /
  rename / delete / persist / ephemeral sweep).
- **`PlanPipeline.swift`** (an extension) — the multi-step planner→executor→critic pipeline.

`maxIterations = 6` bounds every ReAct loop. There is also a `completeHeadless(system:user:)`
path used by Siri inline answers and Writing Tools that runs a bounded completion with
no UI side effects.

### 4.2 Routing — three on-device decisions

| Component | File | Role |
|---|---|---|
| **TaskClassifier** | [TaskClassifier.swift](../Sources/Anu/Agent/TaskClassifier.swift) | Embeds the message with Apple's `NLEmbedding` and picks the nearest task centroid (`casualChat`, `math`, `webInfo`, `codeGen`, `longWriting`, `generalQA`), with a keyword-rule fallback. Runs in milliseconds, no network. |
| **ModelClassifier** | [ModelClassifier.swift](../Sources/Anu/Agent/ModelClassifier.swift) | Maps `(task, confidence, cloudAvailable)` → a `ModelRoute`: `.onDeviceChat`, `.onDeviceAgent`, or `.cloudEscalate`. Confidence floor `0.45`; low confidence → agent path (it can handle anything). Also force-routes to the agent when a device tool (time/calendar/reminders/contacts) is needed. |
| **MessageRouter** | [MessageRouter.swift](../Sources/Anu/Agent/MessageRouter.swift) | Legacy heuristic chat-vs-agent router, retained for reference; superseded by the two classifiers. |
| **RoutingDecision / ResponseParser** | [RoutingDecision.swift](../Sources/Anu/Agent/RoutingDecision.swift) | Parses raw model output into `answerLocally` vs `callTool(…)` vs `escalateToGemini`, by extracting the first balanced `{"tool_call": …}` JSON object (tolerant of code fences and truncation). |

The route is then overridden in two cases: an attached image or "fast mode" forces
`.onDeviceChat`; a needed device tool forces `.onDeviceAgent`.

### 4.3 Three execution modes

1. **Chat** (`chatTurn`) — single-shot, no tools, warm persona, lowest latency. Windows
   the history, formats a chat prompt, streams the answer.
2. **ReAct agent** (`reactLoop`) — the bounded reason→act→observe loop (≤6 iterations).
   Each turn: build an agent prompt with the tool catalog, stream the model, parse a
   `RoutingDecision`, and either finish (`answerLocally`), run a tool (`callTool`), or
   escalate. Tool JSON is hidden from chat and surfaced as a tool card + trace step.
3. **Cloud** (`cloudTurn`) — resolves the provider, **sanitizes PII**, records the
   egress, runs the escalation tool, and folds the result back into history.

### 4.4 Plan → Execute → Critique pipeline

For requests that are *clearly* multi-step, `PlanGate.shouldPlan()`
([PlanGate.swift](../Sources/Anu/Agent/PlanGate.swift)) (length ≥ 24, explicit
sequencing language, lists, or ≥2 distinct task domains) opts the message into the
heavier pipeline in [PlanPipeline.swift](../Sources/Anu/Agent/PlanPipeline.swift) —
*only* when the user has also enabled "deep reasoning":

1. **Plan** — `Planner.makePlan()` ([Planner.swift](../Sources/Anu/Agent/Planner.swift))
   decomposes the goal into ≤6 ordered steps, each assigned to a **specialist**
   (`researcher`, `coder`, `mathematician`, `writer`, `generalist`). One deterministic
   model call; any failure degrades to a single step.
2. **Execute** — each step runs a **headless ReAct loop** (`runReActHeadless`) with the
   specialist's focused system prompt and a *restricted tool subset*
   ([PlanModels.swift](../Sources/Anu/Agent/PlanModels.swift)). Results accumulate in a
   `Scratchpad`. A shared iteration budget is decremented across all steps.
3. **Synthesize** — `synthesize()` combines the scratchpad into one coherent answer
   (single-step plans skip this).
4. **Critique** — `Critic.review()` ([Critic.swift](../Sources/Anu/Agent/Critic.swift))
   returns `.approved` or `.revise(instruction)`; one revision pass max. Ambiguity
   defaults to approved.
5. **Present** — the final text is streamed into the chat bubble.

### 4.5 State, memory & sessions

| Component | File | Role |
|---|---|---|
| **AgentMessage** | [AgentMessage.swift](../Sources/Anu/Agent/AgentMessage.swift) | Message model (user/assistant/toolCall/toolResult/system) with optional `imageData` for vision. |
| **AgentState** | [AgentState.swift](../Sources/Anu/Agent/AgentState.swift) | `AgentStatus` (drives the status bar) and `ReasoningStep`/`ReasoningStepKind` (drives the trace timeline). |
| **MemoryStore** | [MemoryStore.swift](../Sources/Anu/Agent/MemoryStore.swift) | NotebookLM-style editable notes. Every prompt carries a standing profile (newest 3 notes) + query-relevant older notes retrieved by embedding similarity, injected as numbered `[M#]` grounding sources and cited in the trace. |
| **ConversationWindow** | [ConversationWindow.swift](../Sources/Anu/Agent/ConversationWindow.swift) | Trims history to ~2800 chars (~700 tokens) before each prompt, sliding the window to start at a user turn so the template folds cleanly. |
| **ChatSession** | [ChatSession.swift](../Sources/Anu/Agent/ChatSession.swift) | A privacy **sandbox**: independent history, `MemoryScope` (`global`/`isolated`), `ephemeral` ("incognito") flag, optional per-session model override. |
| **PrivacyLedger** | [PrivacyLedger.swift](../Sources/Anu/Agent/PrivacyLedger.swift) | Per-turn, per-session record of every egress (`cloud`, `privateComputeServer`, `mcpServer`, `restHost`, `appLaunch`) with payload summary, redaction count, and byte count. |
| **CloudProvider** | [CloudProvider.swift](../Sources/Anu/Agent/CloudProvider.swift) | Resolves which cloud backend handles escalation (`auto` prefers a configured private server, else Gemini). |

## 5. The Models layer (the swappable brain)

All engines conform to one protocol, `LocalLanguageModel`
(defined in [GemmaModel.swift:7](../Sources/Anu/Models/GemmaModel.swift):7) — note it is
a `Sendable` protocol, and each *implementation* is an `actor`:

```swift
protocol LocalLanguageModel: Sendable {
    var modelName: String { get }
    func load() async throws
    func generate(prompt: String, config: GenerationConfig) async throws -> AsyncStream<String>
    func generate(prompt: String, image: CGImage?, config: GenerationConfig) async throws -> AsyncStream<String>
    func resetSession() async   // drop KV cache on sandbox switch
}
```

### Backends

| Backend | File | Notes |
|---|---|---|
| **LiteRTGemmaModel** (primary) | [LiteRTGemmaModel.swift](../Sources/Anu/Models/LiteRTGemmaModel.swift) | Gemma 4 E4B via MediaPipe `LlmInference`. **KV-cache + session reuse** across turns (feeds only the new delta when the prompt extends the cached prefix, via `SessionContextTracker`). Native vision modality for images. Uses `StreamStopFilter` because MediaPipe generates past `<end_of_turn>`. The entire MediaPipe surface is confined to this one file for an easy future migration to LiteRT-LM. |
| **GemmaModel** (Core ML fallback) | [GemmaModel.swift](../Sources/Anu/Models/GemmaModel.swift) | Gemma 3 4B Core ML, **fixed-shape** `[1, seqLen]` I/O, no KV cache; manual sampling (temperature + top-k/top-p + repetition penalty). iOS 18+ only (int4 per-block quant). |
| **FoundationModelBackend** | [FoundationModelBackend.swift](../Sources/Anu/Models/FoundationModelBackend.swift) | Apple Intelligence on-device model (iOS 26+). Handles Apple's *cumulative* streaming snapshots by emitting only the new suffix. |
| **PrivateCloudModel** | [PrivateCloudModel.swift](../Sources/Anu/Models/PrivateCloudModel.swift) | Streams from the user's private compute server via `PrivateComputeClient`; selectable as a brain *and* an escalation target. Rotates session id on sandbox switch. |
| **ScriptedModel** (`#if DEBUG`) | [ScriptedModel.swift](../Sources/Anu/Models/ScriptedModel.swift) | Deterministic test double, reachable only via `-scripted_model YES`. Recognizes `[[PLANNER]]`/`[[CRITIC]]`/`[[SYNTH]]` sentinels so the whole pipeline is UI-testable. |
| **UnavailableModel** | [GemmaModel.swift](../Sources/Anu/Models/GemmaModel.swift) | Explicit-error placeholder — there is no silent fake in production. |

### Selection — `ModelFactory`

`ModelFactory.makeModel()` ([GemmaModel.swift:241](../Sources/Anu/Models/GemmaModel.swift):241):

1. `#if DEBUG` and `-scripted_model` set → `ScriptedModel`.
2. Otherwise honor the user's `UserDefaults("selected_model")` choice
   (`.appleFoundation` / `.liteRT` / `.coreML` / `.privateCloud` / `.downloadable`).
3. `.automatic` (default) → **`makeAutomatic()`** priority chain:

   ```
   LiteRT (KV-cached)  →  Core ML (fixed-shape)  →  UnavailableModel
   ```

Supporting types: `GenerationConfig`/`ModelConfig`
([ModelConfig.swift](../Sources/Anu/Models/ModelConfig.swift)) hold sampling presets
(`.chat`, `.deterministic`, `.agentFromSettings` — the last clamps temperature ≤0.45 for
reliable tool-call JSON); `ModelCatalog`
([ModelCatalog.swift](../Sources/Anu/Models/ModelCatalog.swift)) is the registry +
availability probe; `ModelManager`
([ModelManager.swift](../Sources/Anu/Models/ModelManager.swift)) is the observable
selection state bound to Settings. Tokenization is protocol-based: `GemmaTokenizer`
(HuggingFace `tokenizer.json`, greedy longest-match + byte fallback) with a
character-level `FallbackTokenizer`.

## 6. Tools & tool use

### The contract — `Tool`

A tool ([Tool.swift](../Sources/Anu/Tools/Tool.swift)) declares a `name`, a
`description`, an optional `JSONSchema` of `parameters`, a `sideEffect`
(`.readOnly` vs `.external(capability:)`), a `requiresConfirmation` flag, and an
async `execute(arguments:) -> String`. The `sideEffect` classification is what the
confirmation gate keys off.

`ToolRegistry` ([ToolRegistry.swift](../Sources/Anu/Tools/ToolRegistry.swift)) is a
`@MainActor` registry. Built-in tools always win name collisions, and connector tools
are swapped in atomically via `replaceConnectorTools()`. Tools are exposed to the model
by name + description + schema, sorted, in the agent system prompt.

### Built-in tools (`Tools/BuiltinTools/`)

| Tool | Device API / permission | What it does |
|---|---|---|
| `CalculatorTool` | none | Safe recursive-descent expression evaluator (rejects NaN/Inf). |
| `WebSearchTool` | network | Brave Search; graceful "unavailable" without a key. |
| `DateTimeTool` | none | Current time + relative date math (grounds "next Friday"). |
| `UnitConverterTool` | none | Offline conversions across 8 categories via `Measurement`. |
| `RemindersTool` | EventKit (Reminders) | Create / list reminders. |
| `CalendarTool` | EventKit (Calendar) | Create / list events. |
| `ContactsTool` | Contacts (read-only) | Look up phone/email by name. |
| `ImageGenerationTool` | Apple Image Playground (iOS 18.4+) | The agent can "draw"; result is presented in chat via an injected callback. |
| `EscalateToGeminiTool` | network → Gemini | PII-sanitizes task + context, records the ledger, calls Gemini. |
| `EscalateToPrivateCloudTool` | network → private server | Same PII funnel/ledger; tells the client *not* to double-record. |

Permission-gated tools degrade gracefully (a denied permission returns a message, never
a crash). `ToolDateParsing` is the shared lenient date parser for the EventKit tools.

## 7. Connectors — external & remote tools

`Sources/Anu/Connectors/` lets the agent use tools that live outside the app, via three
mechanisms, all surfaced as ordinary `Tool`s in the registry.

- **MCP (Model Context Protocol) servers** — remote tool servers (the MCP SDK is kept
  behind `#if canImport(MCP)` / `@_implementationOnly`):
  - `ConnectorConfig` defines `MCPServerConfig` + `MCPAuth` (`none` / `bearer` / `oauth`)
    and persists everything in the **Keychain**.
  - `ConnectorManager` ([ConnectorManager.swift](../Sources/Anu/Connectors/ConnectorManager.swift))
    is the `@MainActor` bridge between Settings and the registry: it connects, lists tools,
    tracks per-server status, and rebuilds the connector tool set on `refresh()`.
  - `MCPConnection` (an actor) holds one live connection (12 s list timeout, 30 s call
    timeout) and converts SDK shapes via JSON round-trips.
  - `MCPOAuth` bridges the SDK's OAuth 2.1/PKCE flow to iOS via
    `ASWebAuthenticationSession`, persisting tokens in the Keychain.
  - `MCPToolProxy` adapts a remote tool into a `Tool` with a **namespaced** name
    `mcp__<server>__<tool>`, marks it `.external(.connector)` + `requiresConfirmation`,
    and logs egress.
  - `MCPCatalog` is a curated one-tap list (DeepWiki, GitHub, Linear, Notion, Sentry,
    Stripe, Semgrep); `MCPRegistryClient` searches the official MCP registry (HTTPS-only).
- **REST connectors** — `RESTConnectorTool` exposes one user-configured endpoint as a
  tool with a fixed host (the agent supplies path/query/body; writes require confirmation).
- **App launching / Shortcuts** — `AppLauncherTool` (`OpenAppTool`, `ShortcutsTool`) opens
  allowlisted URL schemes (`maps`, `tel`, `mailto`, `shortcuts`, …); always
  confirmation-gated and ledgered.
- **UCPDiscovery** — discovers a merchant's MCP endpoint via Google's Universal Commerce
  Protocol (`/.well-known/ucp`); read-only (no checkout).

**Lifecycle of an external MCP tool:** user adds a server (Settings) → optional OAuth
sign-in (browser, token to Keychain) → `refresh()` connects, lists tools, wraps each in
`MCPToolProxy`, and atomically registers them → the model sees them in the prompt →
on a tool call the proxy gate-checks capability + confirmation → executes over the live
connection → logs the egress → returns text to the loop.

## 12. End-to-end: one message, start to finish

Example: *"What's the weather today, and then write me a reminder email about it."*

1. **Entry** — `ChatView` (voice or text) calls `orchestrator.run(userMessage:imageData:)`.
   The user message is appended; the privacy ledger begins a new turn.
2. **Classify** — `TaskClassifier` embeds it (`.webInfo`, high confidence); `MemoryStore`
   injects any relevant `[M#]` notes.
3. **Route** — `ModelClassifier` → `.onDeviceAgent`; the "weather"/"reminder" device-tool
   signal also forces the agent path.
4. **Gate** — "deep reasoning" on + `PlanGate.shouldPlan()` sees the "and then" sequencing →
   the plan pipeline runs (otherwise a single ReAct loop would).
5. **Plan** — `Planner` returns two steps: *researcher → web_search*, then *writer → draft email*.
6. **Execute** — step 1 runs a headless ReAct loop with the researcher's tool subset
   (calls `web_search`, after the capability/confirmation gate, ledgered); the result lands
   in the scratchpad. Step 2's writer drafts the email using that scratchpad context.
7. **Synthesize** — the two results are combined into one answer.
8. **Critique** — `Critic` approves (or asks for one revision).
9. **Present** — the answer streams into the chat bubble; `AgentTraceView` shows every step;
   the privacy chip summarizes egress (here: one Brave search). If "Speak Responses" is on,
   `SpeechSynthesizer` reads it aloud.
10. **Persist** — the session is saved and floated to the top of the drawer.

## 14. Key invariants (quick reference)

- One `@MainActor` orchestrator owns all conversation state; UI and Siri share it.
- Engines are interchangeable behind `LocalLanguageModel`; selection is `LiteRT → Core ML →
  Unavailable` (or the user's explicit pick).
- ReAct ≤ 6 iterations; planner ≤ 6 steps; one critic pass; one revision; 30 s tool timeout.
