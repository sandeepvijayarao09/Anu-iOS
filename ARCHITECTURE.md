# Anu — Architecture & Workflow

Anu is an on-device agentic assistant for iPhone (with a native macOS build).
A Gemma 4 model runs locally through Google's LiteRT-LM runtime. It can call
tools, remember things about you, use skills and connectors, and, only when a
task needs it, hand a sanitised request to a cloud model or to your own Mac.
Every tool call goes through one broker, every secret lives in one vault, and
every byte that leaves the device is recorded.

About 32,500 lines of Swift in 189 files under `Sources/Anu`, plus five app
extensions and a macOS target, all generated by one script (§13).

This is the only architecture document. `Docs/ARCHITECTURE.md` points here.
Docs describe what exists: a change that alters the design updates this file in
the same change.

## 1. The shape of it

```
                    ┌──────────────────────────────────────┐
   you ───────────▶ │  UI (SwiftUI) · Voice · App Intents   │
                    │  widget · share · writing · keyboard  │
                    └──────────────────┬───────────────────┘
                                       │ a message (+ photos / PDF / voice note)
                                       ▼
                    ┌──────────────────────────────────────┐
                    │  AgentOrchestrator  (@MainActor, one) │
                    │  Direct tier → DeviceGuard → classify │
                    │  → memory → route → chat/agent/plan/  │
                    │  cloud                                │
                    └───┬──────────────┬──────────────┬────┘
                        │              │              │
              ┌─────────┘              │              └─────────┐
              ▼                        ▼                        ▼
     ┌────────────────┐     ┌────────────────────┐    ┌──────────────────┐
     │ Model layer    │     │ ToolBroker         │    │ MemoryStore v2   │
     │ LiteRTLMModel  │     │ schema · policy ·  │    │ facts + sources, │
     │ Gemma 4 E2B/E4B│     │ taint · approval · │    │ learned on device│
     │ 8,192 tokens   │     │ replay · receipts  │    └──────────────────┘
     └────────────────┘     └─────────┬──────────┘
                                      │ the only way a tool runs
              ┌───────────────────────┼──────────────────────────┐
              ▼                       ▼                          ▼
     ┌────────────────┐     ┌────────────────────┐    ┌──────────────────┐
     │ Built-in tools │     │ Skills             │    │ Connectors       │
     │ calendar, calc,│     │ SKILL.md + JS      │    │ MCP · REST · UCP │
     │ photos, phone… │     │ sandbox            │    │ Gmail · A2A · Mac│
     └────────────────┘     └────────────────────┘    │ Gemini · private │
                                                      └────────┬─────────┘
                                   secrets only via Vault ◀────┤
                                                               ▼ always
                                                      ┌──────────────────┐
                                                      │  PrivacyLedger   │
                                                      └──────────────────┘
```

**Three rules hold the design together:**

1. **The model proposes; the Tool Broker decides.** Every tool call, from the
   ReAct loop, the planner's sub-agents, the Direct tier or a cloud route,
   goes through `ToolBroker` (§4).
2. **Anything that leaves the device passes through a tool**, and that tool
   records an `EgressDestination` in the `PrivacyLedger`. There is no second
   path out.
3. **Models never see secrets.** Keys and tokens live in the `Vault`, which
   attaches a value only to an HTTPS request for the host it is bound to (§5).

## 3. A turn, end to end

Entry point: `AgentOrchestrator.run(...)` (`Agent/AgentOrchestrator.swift`).
Each turn gets a fresh broker `RunState`.

```
 0. TAINT?        a voice note in view taints the run from the start
 1. DIRECT TIER   exactly one phone command, no attachments?  → one tool call, no model
 2. GUARD         DeviceGuard.evaluate → GuardPlan (heat, low battery)
 3. CLASSIFY      TaskClassifier (NLEmbedding nearest-centroid)
                  a photo or PDF in view taints the run
 4. MEMORY        MemoryStore.context(for:) unless the session is isolated
 5. ROUTE         Fast mode or media in view       → on-device chat
                  otherwise ModelClassifier.route  → chat · agent · cloud
                  needsDeviceTool / a named skill  → chat becomes agent
                  Smart routing (optional)         → EscalationRouter asks the model
                  a voice note in view             → never cloud
 6. EXECUTE       chatTurn · reactLoop · planPipeline · cloudTurn
 7. CHECK         ActionClaims against the broker's record (one repair)
 8. RECORD        receipts + AnswerDetails on the answer; ledger per egress
 9. PERSIST       session, memory capture (learned later), Spotlight
```

### The Direct tier

`AgentOrchestrator+Direct.swift`, with `PhoneCommands.match`. A message that
is exactly one phone command ("turn on the flashlight", "set a timer for 5 minutes")
becomes one tool call through the broker. The reply is the tool's own result
(`directAnswer(for:)`), never a model's words, and the caption reads
"On device · no model needed". Commands iOS doesn't let apps perform (volume,
Focus) get an honest answer instead. An unregistered tool or invalid
arguments fall through to the normal route. The Direct tier starts untainted.

### Routing

- `ModelClassifier`: `confidenceFloor = 0.45`; below it, chat. Casual chat and
  general questions → chat; math → agent; web → agent when search or a cloud
  provider is available; code and long writing → cloud when available, else
  chat.
- `DeviceGuard` (`Agent/DeviceGuard.swift`) watches thermal state (`.serious`
  or worse) and battery (below `lowBattery = 0.15` and not charging). When it
  guards: no planner, no escalation judge, answers capped at 256 tokens.
- `EscalationRouter` (Settings → Smart routing, off by default) asks the
  on-device model `LOCAL`/`ESCALATE` with an 8-token answer and a 10 s limit.
- `CloudProvider`: `auto`, `private`, `gemini`, `mac`. Auto prefers your
  private compute server, then your Mac, then Gemini.

### The modes

- **`chatTurn`**: single shot, no tools. Fast mode forces every turn here.
- **`reactLoop`**: reason → tool call → observe, until the model answers or
  hits the budget. Each call shows as a card and in the reasoning trace.
- **`planPipeline`**: Planner → sub-agents → synthesis → Critic. Only with
  Settings → Deep reasoning on, the guard allowing it, and `PlanGate.shouldPlan`.
- **`cloudTurn`**: the escalation tool (Gemini, private compute or Mac) runs
  through the broker. PII is stripped first and the redaction count shown.

### Fitting the context: ToolSelector and the 8,192-token window

`LiteRTLMModel.contextTokens = 8_192` (`Models/LiteRTLMModel.swift`) is the
engine's whole working space per answer: instructions, tools, history, message
and reply. 4,096 overflowed on device (2026-11-13).

`ToolSelector` (`Agent/ToolSelector.swift`) decides which tool specs go into
the prompt. `datetime` and `calculator` always go, plus the active provider's
escalation tool. Every other tool scores 3 × keyword hits in the latest
message plus hits in the previous two (keywords from its name, description and
a `triggers` table), and tools are added by score within `budgetTokens =
1_300`. Companions ride along (`load_skill` brings `run_js` and `run_intent`).
If the engine still reports the prompt too long, the turn retries once with
`ToolSelector.minimal`. `SkillDetector` additionally scopes Gmail tools to
email turns only.

`ConversationWindow` keeps about 800 tokens of history, dropping the oldest and
always starting on a user turn. `TokenCalibration` learns the real
characters-per-token ratio from the engine (starting at 3.5 for prose, 2.5 for
JSON).

### Tool calls

`ResponseParser` (`Agent/RoutingDecision.swift`) accepts the documented JSON
contract and Gemma 4's own syntax, because Gemma 4 does not reliably follow
the JSON contract in the prompt:

```
{"tool_call": {"name": "calculator", "arguments": {"expression": "2+2"}}}   ← documented
<|tool_call>call:calculator{expression: "2+2"}<tool_call|>                   ← what it often emits
```

Argument objects alternate between strict JSON and JavaScript literals between
runs of the same prompt; `repairLooseJSON` runs only after a strict decode
fails, so valid JSON is never touched.

> If a third dialect shows up, constrain the prompt; don't add a third repair
> branch.

### The answer is checked against what happened

`ActionClaims` (from Anu Android ADR-027): an answer that claims an action the
broker didn't record ("I've sent the text…") or leaks tool-call markup gets
one repair, and the bad answer is never shown or saved. If the repair still
claims it, the answer ends with "Note from Anu: nothing was actually created
or sent." Under every answer, `ReceiptList` lists what really happened, in
each tool's own words.

### About this answer

The caption under an answer (`AnswerCaption`, `UI/AboutAnswerSheet.swift`)
opens **About this answer**: where your data went first, then the model and
backend, the route ("Chat", "Agent", "Planner", "Cloud"), memory notes used,
tools used, receipts, and speed (first word, total, tokens in/out, whether the
engine counted them). `AnswerDetails` keeps references and numbers, never
content.

## 4. Tool Broker (the trust core)

Ported from Anu Android's `ToolBroker` (`Agent/ToolBroker.swift`). Tools never
decide whether they run; they answer the broker's questions from the validated
payload: `risk(for:)`, `describe(_:)`, `sendsTo(_:)`,
`returnsUntrustedContent(for:)`, `editableFields`, `approvalNote(for:)`,
`timeout`.

For each call, in order:

1. **Known tool?** A skill called as if it were a tool gets told to
   `load_skill` first.
2. **Budget:** `maxToolCallsPerTurn = 12`.
3. **Schema** (`ToolArguments.canonicalize`): unknown top-level keys dropped,
   nulls treated as absent, required keys enforced, unambiguous coercions
   ("5" → 5), enums in the schema's spelling. What you approve is exactly
   what runs. Invalid calls never run.
4. **Capability switch** (e.g. app launching off) blocks before anything asks.
5. **Replay:** a non-read call is keyed by `sha256(turn | tool | payload)`; the
   same call in the same turn returns its stored result instead of acting twice.
6. **Policy and approval:**

   | Risk | Example | Runs by itself? |
   |---|---|---|
   | `read` | calendar list, web search, `gmail_search` | Yes, unless the run is tainted **and** the call sends data to a host |
   | `writePrivate` | a reminder, an event, `gmail_create_draft` | Yes, unless the run is tainted |
   | `writeExternal` | text/call/email, open an app, a Shortcut, every MCP / A2A tool, REST writes, `gmail_send`, escalations | **Never**: always the exact payload |
   | `destructive` | (none yet) | Never |

   `ApprovalCenter` → `ApprovalSheet` shows the tool's summary, why it asks,
   where it goes, and the payload field by field. **Edit** changes only the
   tool's `editableFields`; saving approves nothing — the broker re-checks the
   edit and asks again ("Edited by you"). No answer in 10 minutes
   (`ApprovalCenter.timeout = 600 s`) is a denial.
7. **Run** under the tool's timeout: `ToolBroker.toolTimeout = 30 s` by
   default, `escalationTimeout = 180 s` for the Gemini, private compute and
   Mac escalations. Then record: `ToolAuditLog` (Settings → Activity, 500
   entries, encrypted on device) and a receipt for any non-read call.

**Taint (P4).** A result from a tool that returns content written by others
taints the run for the rest of the turn; nothing un-taints it. Sources: web
search, `read_text`, `read_pdf`, Gmail reads, every MCP, REST and A2A result,
clipboard and file reads, calendar and reminder lists, `run_js`, an added
skill's instructions, and a voice note, photo or PDF in view. A tainted run
loses its automatic permissions: private writes and data-sending reads ask.

Refusals tell the model why, by code (`declined`, `no_answer`, `not_allowed`,
`budget`, `cancelled`), so it can tell a person's "no" from a rule.

## 5. Vault and SecureFile

### Vault (`Vault/Vault.swift`, `VaultModels.swift`)

- Every secret (Gemini and Brave keys, MCP bearer and REST auth tokens, Gmail
  tokens, the Mac brain token) is a Keychain item in service
  `com.anu.app.vault`, `WhenUnlockedThisDeviceOnly`, optionally with
  `.userPresence` access control. Only API keys and OAuth tokens may skip
  user presence.
- Each item has **bound hosts** and **allowed callers** (`VaultCaller`:
  `gemini`, `web_search`, `connectors`, `gmail`, Mac brain). The value is
  stored with its binding, so changed metadata can't redirect it.
- Code never reads a secret to build a request. It calls
  `Vault.authorize(request, use: SecretUse(ref:header:caller:))`, which checks:
  the item exists, the URL is HTTPS, the host is bound, the caller is allowed,
  then sets the header. `authorizeFormField` does the same for a form body
  field. Vault-authorised requests refuse every redirect (`VaultNoRedirects`),
  because URLSession forwards custom headers to wherever a redirect points.
- Every send, refusal, reveal, add and delete goes in the vault's activity log
  (200 entries).
- **Settings → Vault** lists each item with where it may go and when it was
  last used. A value is shown only after Face ID / passcode
  (`revealForUser`), only while the item's sheet is open, and is hidden when
  the app leaves the foreground. Settings never shows a saved key back.
- `ConnectorSecrets.seal` moves inline MCP / REST tokens out of connector
  configs into the vault, each bound to its own endpoint's host.
  `Vault.migrateLegacyKeys` moves old `KeychainStore` keys in.

### SecureFile (`Vault/SecureFile.swift`)

On-device stores are written with AES-256-GCM (header `ANUE1`), atomically,
with `.completeFileProtection`, and excluded from backup. The 32-byte key is in
the Keychain (`data.key`, `AfterFirstUnlockThisDeviceOnly`); the App Group
copy uses `AppGroupDataKey`. Old plain JSON still loads and is encrypted on the
next save. Users: conversations, sessions, memory, Privacy Ledger, Activity
(audit), Gmail auth state, A2A agents, added skills, shared voice notes.

Without a Keychain entitlement (an unsigned build) SecureFile falls back to
plain bytes and the Vault cannot store anything, which is why the tests are
run with ad-hoc signing (§14).

## 6. The model layer

`ModelFactory.makeModel()` (`Models/GemmaModel.swift`) resolves the user's
choice from `ModelCatalog`, all Gemma 4 on LiteRT-LM:

| | Size | RAM floor | Source |
|---|---|---|---|
| Automatic | — | — | bundled E4B → downloaded E4B → downloaded E2B → `UnavailableModel` |
| E4B | 3.4 GB | 12 GB | bundled (`Anu/gemma4e4b.litertlm`) or downloaded |
| E2B | 2.6 GB | 8 GB | downloaded from the allowlist (`ModelAllowlist`) |

`UnavailableModel` throws a specific reason rather than faking a reply.
`ScriptedModel` exists only in DEBUG, reachable only through
`-scripted_model YES`, and backs the UI tests.

`LiteRTLMModel` drives LiteRT-LM's `Conversation`. Anu's prompts are built as
Gemma-templated strings; `GemmaPromptParser` turns them back into turns so the
runtime applies its own template. Vision loads only when a picture is in view
(at most 4 per conversation), audio only for voice notes. GPU on device, CPU
in the Simulator. **Prompt lab** (Settings → Performance) runs a prompt on the
same engine with no memory, tools or history, with templates (Free form,
Rewrite, Summarize, Code), sampling controls and Stop.

Apple Foundation Models are used only in the writing and keyboard extensions
(§11), where Gemma can't load.

## 7. Memory v2

`Agent/MemoryStore.swift`, `MemoryExtraction.swift`, `MemoryLearner.swift`,
`MemoryRelevance.swift`.

- **Facts with provenance.** A `MemoryFact` is subject / predicate / value in
  one of 8 sections (identity, people, work, routines, preferences, goals,
  places, notes), with confidence, origin (`userStated` / `inferred`), status
  (`active`, `superseded`, `upcoming`) and the `MemoryEvent`s (messages) it
  came from. Free-text memories are facts with predicate `note`.
- **Learned on device, later.** `captureChat` queues each user message
  (never for isolated or ephemeral sessions). `FactExtractor` runs on the
  on-device model only, no tools, deterministic, JSON out, one repair attempt.
  Runs happen in a `BGProcessingTask` on external power, after 90 s of quiet
  chat, on entering the background, or from **Learn now** — never mid-chat, and
  not in Low Power Mode or when hot. A fact is kept only if its quote is really
  in the message.
- **Filters.** Messages with passwords, PINs, API keys or one-time codes are
  dropped; ID, IBAN and card numbers are replaced. Inferred facts start at 0.6
  confidence and rise with re-mention; single-valued predicates (name,
  lives_in, manager…) supersede the old value; an inferred fact never replaces
  one you stated; deleted or corrected facts are never re-learned from chat.
  Cap: 300 facts, 1,000 events.
- **Retrieval.** `MemoryRelevance.pick` (8 facts, 600 chars) scores words and,
  where on-device embeddings exist (`NLContextualEmbedding`, else
  `NLEmbedding`), meaning. The block (400-token budget) is numbered `[M1]…`,
  marks unconfirmed and private facts, and goes into chat, agent and planner
  prompts. Memory never goes to the cloud.
- **Memory Inspector** (Settings → Memory): search, sections, add in your own
  words, confirm, correct, delete, "Where it came from" with Forget this
  message, history, Forget Everything.
- Stored in `Documents/memory.json` through SecureFile.

## 8. Skills

`Skills/` and the bundled `Anu/Skills/` folder (Settings → Skills).

- A skill is a folder with a `SKILL.md` (front matter `name`, `description`,
  optional `require-secret`, `homepage`; 100 KB max) and up to 8
  `scripts/*.js`. Built in: `calculate-hash`, `email-draft`, `unit-table`,
  `word-count`. Each has a switch.
- The model sees only each enabled skill's name and description, in the
  `load_skill` tool. `load_skill` returns the whole SKILL.md; `run_js` runs a
  script; `run_intent` (send email/SMS, call, maps, URL) is `writeExternal`.
- `JSSandbox`: a bare JavaScriptCore context, no network, timers, files or
  native bridges; data passed as a string, never as code; 4,000-char input and
  output; 5 s wall-clock limit.
- Add from File or URL (HTTPS only, downloaded once, logged to the ledger,
  stored through SecureFile). An added skill's instructions, and any script
  output, taint the run (§4).

## 9. Connectors and cloud

`ConnectorManager.refresh()` builds the connector tools and installs them with
`ToolRegistry.replaceConnectorTools`, which swaps exactly the previous set.
Built-in tools win a name clash. Configs live in the Keychain; their tokens are
sealed into the vault.

| Connector | How | Tool names / risk |
|---|---|---|
| **MCP** | Swift MCP SDK over HTTPS; bearer or OAuth (dynamic client registration, `anu://oauth-callback`, sign-in only from a tap); 7-server catalog (DeepWiki, GitHub, Linear, Notion, Sentry, Stripe, Semgrep) and the public MCP registry | `mcp__<server>__<tool>`, always `writeExternal`, results taint |
| **REST** | one HTTP API as one tool, host fixed; the model supplies only path, query, body | `rest__<name>`; GET/HEAD `read`, else `writeExternal` |
| **UCP** | Universal Commerce Protocol: `/.well-known/ucp`, falling back to Shopify's `/api/mcp` | as MCP |
| **Gmail** | your own iOS OAuth client ID, PKCE, scopes `gmail.readonly`, `gmail.compose`, `gmail.send`; tokens in the vault bound to Google's hosts | `gmail_search`, `gmail_read_thread` (read, taint), `gmail_create_draft` (writePrivate), `gmail_send` (writeExternal). See `Docs/GMAIL_SETUP.md` |
| **A2A** | client only: agent cards from `/.well-known/agent-card.json`, JSON-RPC `message/send`; plain HTTP only to local addresses | `a2a_<name>`, writeExternal, results taint |
| **Your Mac** | Ollama on your Mac: plain HTTP on the local network, or HTTPS via `Scripts/mac-brain.py` with a pinned self-signed certificate and a token from the pairing code (`anu-mac://host:port?pin=…&token=…`) | `escalate_to_mac`, text only. See `Docs/MacBrain.md` |
| **Gemini** | key in the `x-goog-api-key` header (never the URL), redirects refused | `escalate_to_gemini` |
| **Private compute** | your own server (`Docs/PrivateComputeServer.md`) | `escalate_to_private_cloud` |
| **Apps** | `run_shortcut`, `open_app`, `contact_action`, navigate, share; behind the app-launch switch | writeExternal |

`EgressDestination` (`Agent/PrivacyLedger.swift`) enumerates every way out:

```swift
case cloud(model:)
case privateComputeServer(endpoint:)
case mcpServer(name:host:)
case restHost(name:host:)        // also Gmail and skill downloads
case appLaunch(scheme:target:)
case mac(host:)
case a2aAgent(name:host:)
```

## 10. Voice and media

**Voice** (`Voice/`):
- `VoiceLoop` wires the pure `LiveTalk` loop (listen → send at a pause → speak
  → listen) to audio. `Endpointer` waits 700 / 1,100 / 1,800 ms depending on
  how finished the words sound; `BargeInDetector` lets you talk over Anu; the
  first clause of an answer is spoken early. Four quiet listens pause voice
  mode.
- **Hey Anu** (`WakePhrase`, `WakeLoop`): foreground only, on-device
  recognition required; anything that isn't the wake phrase is dropped.
- Dictation uses `SFSpeechRecognizer` with on-device recognition when the
  device supports it; speech output is `AVSpeechSynthesizer`.
- **Voice notes** (16 kHz mono, up to 5 minutes) are transcribed on device:
  Gemma 4's audio input first, then Apple's `SpeechAnalyzer` /
  `SFSpeechRecognizer`. A voice note in view taints the run and blocks cloud
  escalation.

**Media**:
- Up to 4 photos and one PDF per message. Photos are resized to 1,024 px and
  re-encoded (which strips metadata); screenshots go through `ScreenSecrets`,
  which blacks out codes and card numbers in the pixels first. While media is
  in view, cloud and external tools are refused (`mediaEgressRefusal`).
- PDFs: short ones go whole, long ones are read in pieces with no tools;
  scanned PDFs fall back to page pictures.
- `generate_image` uses Image Playground's `ImageCreator` (Apple
  Intelligence devices). `read_text` uses Vision OCR. Live camera
  (`LiveCameraView`) runs Vision detection at most 5 fps, pauses when the
  device is critical, and sends a frozen frame through the normal photo path.
- `ShownSecrets` holds back a code-shaped number in the answer stream and
  masks it.

## 11. Extensions

All share the App Group `group.<bundle prefix>` (`Workflows/AppGroupStore.swift`).

| Extension | What it does |
|---|---|
| **AnuWidget** | small/medium widget listing saved workflows; a tap runs `RunWorkflowIntent` |
| **AnuShare** | text and URLs to `InboxStore`; up to 4 photos and a PDF to `SharedMedia`; audio decoded to a voice note sealed with SecureFile |
| **AnuWriting** | "Rewrite with Anu" in the share sheet: improve, shorter, formal, friendly, proofread, summarize |
| **AnuKeyboard** | a full keyboard with an AI strip (the writing actions plus Ask Anu, Expand, Emoji, Continue, Reply). No dictionary, suggestions or history; no AI in password, code or card fields |

The writing and keyboard extensions run Apple's on-device Foundation model
(`ExtensionWriting.appleEngine()`, iOS 26+) because Gemma can't load in an
extension. When it's unavailable, a request is handed to the app through
`WritingHandoffStore` (App Group, one request per source, 15-minute lifetime);
the app runs it on Gemma when next opened and leaves the result for the
extension to preview. The keyboard hands off only with Full Access. Nothing is
replaced until you tap Replace or Insert. Settings → Keyboard explains setup
and what it can see.

## 12. Siri & App Intents

15 `AppIntent` types ship; `AnuShortcuts` registers **10 App Shortcuts** (22
phrases), the iOS maximum, enforced at build time by
`appintentsmetadataprocessor`. Adding one means retiring one. Timer, alarm,
proofread, live camera and search are usable from Shortcuts without a phrase.

`SearchAnuIntent` adopts the `.system.search` assistant schema, the only one
that fits an assistant. (The `.mail.*` family is write-only, with no search or
read schema.) Adopting a schema is a promise: "search … in Anu" leads to real
search in `SessionListView`.

**What iOS will not give you** (verified against the SDK): no Messages read API
(`Messages.framework` is iMessage *extensions* only) and no Mail read API
(`MailKit` isn't in the iOS SDK). Mail comes through account APIs, which is why
Gmail is a connector.

## 13. The generated project

`Anu.xcodeproj` is **generated** by `generate_xcodeproj.py`; never edit it by
hand, and don't commit local regenerations unless the file list changed.

```bash
python3 generate_xcodeproj.py      # after adding any file
ANU_TEAM_ID=ABCDE12345 ANU_BUNDLE_PREFIX=com.example.anu python3 generate_xcodeproj.py
```

- `ANU_TEAM_ID` → `DEVELOPMENT_TEAM` (empty by default: Simulator builds).
- `ANU_BUNDLE_PREFIX` (default `io.github.sandeepvijayarao09.anu`) → every
  bundle ID (`.tests`, `.uitests`, `.widget`, `.share`, `.writing`,
  `.keyboard`) and the App Group `group.<prefix>`.
- Targets: `Anu` (iOS 17+), `AnuTests`, `AnuUITests`, `AnuWidget`, `AnuShare`,
  `AnuWriting`, `AnuKeyboard`, `AnuMac` (macOS 15). Schemes: `Anu` (tests both

- Packages: MCP (remote) and LiteRT-LM (local, `ThirdParty/LiteRTLM`).

## 14. Testing

```bash
xcrun simctl create anu-tests "iPhone 17 Pro"     # your own simulator
xcodebuild test -project Anu.xcodeproj -scheme Anu \
  -destination 'platform=iOS Simulator,id=<UDID>' \
  -only-testing:AnuTests \
  -skip-testing:AnuTests/ContactsIntegrationTests \
  -skip-testing:AnuTests/EventKitIntegrationTests \
  -skip-testing:AnuTests/PhotosIntegrationTests \
  CODE_SIGN_IDENTITY=- CODE_SIGN_STYLE=Manual DEVELOPMENT_TEAM=
# UI suite: the same with -only-testing:AnuUITests
```

**Sign ad hoc** (`CODE_SIGN_IDENTITY=-`). An unsigned build has no Keychain
entitlement, so the Vault can't store anything and vault tests fail.

UI tests launch with `-scripted_model YES` and reset flags (`-reset_sessions`,
`-reset_connectors`, `-reset_privacy`, `-reset_workflows`, `-reset_vault`), so
they are deterministic and start clean. Memory has no reset flag; the memory
UI test deletes what it adds.

Measured 2026-11-13 on an iPhone 17 Pro simulator (iOS 27): **902 unit
tests** (898 run, 4 skipped by gates) and **30 UI tests** (22 run, 8
skipped by gates) in the default run. Gated tests report as skipped, so a green default run doesn't cover them:

| Flag (`TEST_RUNNER_` prefix) | Unlocks |
|---|---|
| `VERIFY_DRIVERS=1` | 5 GUI drivers that flake under load (Private Compute screen, agentic pipeline, connectors UI, reach/model screens, Prompt lab run + Stop) |
| `REAL_MODEL_TEST=1` | 4 real-engine unit tests (incl. multi-turn KV reuse) and 1 UI test; needs the model |
| `LIVE_CONNECTOR_TEST=1` | live DeepWiki MCP + registry (network) |
| `MCP_TEST_URL=<url>` | a *fixture* MCP server with a `ping` tool |

**Permission-dependent tests** (EventKit, Contacts, Photos) skip unless the app
holds the grant, and `xcodebuild test` reinstalls the app, which resets TCC.

## 15. Traps worth knowing

**Never put a tool's dependency behind `@MainActor`.** XCTest blocks the main
thread to drive an `async` test, so a tool awaiting main-actor state deadlocks
and the suite hangs with no output. `CalendarAccess` is deliberately not
`@MainActor`; only its `@Published` bump hops to main.

**`EKEventStore` must be long-lived** to receive `.EKEventStoreChanged`, and
must be `reset()` after a change before its cached objects are trustworthy.

**`AVSpeechSynthesizer` needs a delegate** or `isSpeaking` never returns to
false.

**`Canvas` clips to its frame.** A glow drawn past the edge renders as a square.

**The iOS Simulator has no audio input** (`error -10879`). Mic-driven features
can only be verified on hardware. TTS output works there.

**A SwiftUI `Label` with an identifier surfaces as several elements** in XCUI;
query with `.firstMatch` or a predicate.

## 16. Design system

- `UI/Typography.swift`: five steps. `anuLabel` (13pt) is the floor for
  anything load-bearing; `anuMeta` (12pt) is for timestamps and captions.
- `UI/DesignSystem.swift`: `Space` (4pt scale), `Radius` (3 steps), colour.
- **Motion follows real signal.** The voice orb animates only while listening,
  thinking or speaking; idle, it draws nothing (Anu Android measured its idle
  loop at 43% of a CPU core).
- **The accent marks one thing per view**: the primary action, the active
  selection, or your own message. **Orange in the Privacy Ledger means bytes
  left the device**; nothing else is coloured there.
